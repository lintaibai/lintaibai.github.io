taibai CLI ​

把组件源码拷进你的项目，你拥有全部代码，随便改。 思路参考 shadcn/ui，基于 element-plus。

快速开始 ​

全局安装（可选） ​

bash
1. 安装
npm install -g taibai@latest

2. 验证安装是否成功
taibai --version
# 或者
taibai -v

3. 运行你的命令
taibai list

4. 卸载
npm uninstall -g taibai

⚠️ 常见问题排查：权限错误 (EACCES)，Mac 上执行 sudo npm install -g taibai@latest。

不想全局安装的话，所有命令都用 npx taibai@latest 跑，下面示例统一用这种写法。

1. 初始化项目（每个项目只做一次） ​

bash
cd your-vue-project
npx taibai@latest init

直接回车用默认值即可，组件会放到 src/components/widgets/，初始化时可改成 src/components。 配置写在项目根目录的 taibai.json：

json
{
  "componentsDir": "src/components",
  "alias": "@"
}

2. 查看可用内容 ​

bash
npx taibai@latest list

会列出指令、样式、工具函数，以及业务组件库里全部 23 个组件。

3. 添加 ​

bash
# 单个
npx taibai@latest add ProEmpty

# 多个
npx taibai@latest add ProEmpty Pagination TypeWriter

# 业务组件库全部
npx taibai@latest add all
  • 组件落地到 <componentsDir>/<组件目录>/，多文件组件整目录拷入（如 Grid/ 含 index.vue 与 components/）；
  • 组件内部用 @/components/... 互相引用，安装时自动改写成你的 alias 前缀，拷过去就能跑；
  • 若还缺 src/utils、src/hooks 等支撑目录，CLI 会提示，补一句 add all 最省事。

4. 在 vue 文件里直接用 ​

vue
<script setup>
import ProEmpty from '@/components/ProEmpty/index.vue'
import Pagination from '@/components/Pagination/index.vue'
</script>

<template>
  <ProEmpty />
  <Pagination v-model:current-page="page" v-model:page-size="size" :total="100" />
</template>

拷过去的文件就是你的，打开改样式、改逻辑都行。

组件命名规范 ​

组件名 = 依赖层级前缀 + 语义后缀。前缀回答“它依赖什么”，后缀写清“它是什么”，看名字就能判断安装成本。

前缀定位依赖示例
Pro依赖 UI 组件库element-plus 等第三方 UI 库ProEmpty（空状态，基于 el-empty）、ProTable
BizBusiness，业务组件业务接口、路由、权限、登录态BizEmpty（如 UserSelect、Message）
App平台级组件平台壳、布局、主题、多端适配AppEmpty（如布局壳、路由壳）
Basic基础但功能完整不依赖第三方库，可依赖自写组件BasicEmpty（如 BasisForm、BasisTable）
无前缀最基础不依赖组件库或自写组件Empty（如 Icon）

约定：

  1. 先看依赖，再看语义：能独立成立的最基础件用无前缀；一旦引入 element-plus 等 UI 库，就升到 Pro。
  2. 带业务语义（接口、权限、组织架构）用 Biz；平台能力（布局、路由壳、主题）用 App。
  3. 前缀只表达依赖层级，后半只表达用途，不要叠加两个前缀（ProBizXxx 不推荐）。
  4. 改名时同步更新目录、scripts/copy-components.mjs 的 META、CLI 清单和文档；命令只认新名，不保留旧名别名。
  5. 本次改名示例：NoData → ProEmpty，因为它依赖 element-plus 的 el-empty；ProTable、BasisForm 等历史命名保持不动，新组件按本规范起名。

组件使用 ​

23 个组件逐个展开，每个组件都按 安装 → 使用 → 属性 → 扩展 四步写。

通用规则只说一次：命令名就是目录名（ProTable 或 pro-table 都认），文件拷到 <componentsDir>/<组件目录>/，多文件组件整目录拷入；组件内部的 @/components/... 引用会按 taibai.json 里的 alias 改写，装完直接 import 就能跑；目标文件已存在时会询问是否覆盖，默认不覆盖。组件基于 element-plus，用到表格、弹窗、分页的组件需要项目里已安装并注册了对应组件。

打字机TypeWriter ​

展示 · 打字机逐字输出，可重播。

安装 ​

bash
npx taibai@latest add TypeWriter

落地 src/components/TypeWriter/：

text
TypeWriter/
├── index.vue     # 组件本体：props、逐字逻辑、光标
└── atoms.css     # 组件自带的 10 条原子声明，由 <style src> 自动挂载

单装 TypeWriter 不需要另外引 nexus.css。

使用 ​

vue
<script setup>
import TypeWriter from '@/components/TypeWriter/index.vue'
</script>

<template>
  <TypeWriter title="<p>你好，我是 taibai 的打字机组件。</p>" :type-speed="30" :delay="300" />
</template>

title 走 v-html，可以写 HTML；标签不会被逐字打出来，只对文本逐字输出。

属性 ​

参数类型默认值说明
titlestring必填要输出的内容，允许 HTML 字符串
typeSpeednumber30每个字符的间隔毫秒数，越大越慢
delaynumber300开始输出前的等待毫秒数

Expose：

名称类型说明
isTypingRef<boolean>是否正在输出；默认 false，光标不显示
startTyping() => Promise<void>从第一个字符重新开始输出

扩展 ​

想改的东西改哪里
光标颜色、闪烁节奏atoms.css 的 .anim-cursor-blink
光标与文字的间距atoms.css 的 .mglf2（当前 2px）
换行、行高、断词index.vue 模板上的 leading-1-6、break-words 等原子类
打字速度、输出逻辑index.vue 的 typeText，或外面传 typeSpeed

搜索表单SearchForm ​

表单 · 搜索条件区，由列配置生成查询表单。

安装 ​

bash
npx taibai@latest add SearchForm

落地 src/components/SearchForm/：index.vue、components/SearchFormItem.vue。

使用 ​

vue
<script setup>
import { reactive } from 'vue'
import SearchForm from '@/components/SearchForm/index.vue'

const searchParam = reactive({ name: '' })
const columns = [{ prop: 'name', label: '姓名', search: { el: 'input' } }]

const handleSearch = params => console.log('查询', params)

<template>
  <SearchForm

    :search-col="{ xs: 1, sm: 2, lg: 3 }"
    :search="handleSearch"
    :reset="handleReset"
  />
</template>

search / reset 是函数 props，由组件内部在点按钮时调用，不是 emit。

属性 ​

参数类型默认值说明
columnsColumnProps[][]列配置，search 字段决定搜索项
searchParamRecord<string, any>{}搜索参数对象

三个样式互相独立，可单装。TypeWriter 目录下自带 atoms.css（只含它用到的 10 条声明），装组件时一起拷进去、由组件里的 <style src="./atoms.css"> 挂载，所以单装 TypeWriter 就能直接显示，不必先引 nexus.css；其他组件仍按需引入全局原子库。

工具函数拷到 src/utils/modules/，按需 import：

ts
import { formValidate } from '@/utils/modules/formValidate'

// 在 element-plus 表单 rules 里用
rules: [
  { validator: formValidate('phone'), trigger: 'blur' },
  { validator: formValidate('idCard'), trigger: 'blur' },
  { validator: formValidate('email'), trigger: 'blur' }
]

内置校验类型：phone / password / idCard / email / plateNumber / chinese / fullName / creditCode / webUrl 等。

命令说明
npx taibai@latest add form-validate常用表单校验规则（手机号/身份证/邮箱/密码等正则）

如何卸载 / 删除 ​

taibai 是把源码拷进你的项目，拷过去的文件就是你的，删除就是直接删文件：

类型删除什么同时记得去掉
组件删 <componentsDir>/组件名/ 整个文件夹文件里的 import 与模板里的使用
指令删 src/directives/modules/指令名.tsmain.ts 里的 app.directive(...) 注册与模板里的 v-xxx
样式删 src/styles/modules/nexus.css / nexuspx.css / animations.cssmain.ts 对应的 import
工具函数删 src/utils/modules/xxx.ts文件里的 import

不需要 npm uninstall，组件没进 node_modules，拷过来的就是你自己的源码。

补充说明：

  • 覆盖：目标文件已存在时，add 会询问是否覆盖，默认不覆盖；非交互环境（CI）下保持不覆盖，自己改过的文件不会被悄悄替换。
  • 只想改一点：直接改拷过去的源码，taibai 不会再回头动它。

常用命令速查 ​

bash
npx taibai@latest init              # 初始化项目（写 taibai.json）
npx taibai@latest list              # 查看全部组件 / 指令 / 样式 / 工具
npx taibai@latest add <名称>        # 添加单个或多个
npx taibai@latest add all           # 装业务组件库 + 支撑目录
npx taibai@latest --help            # 帮助

本地开发（维护这个 CLI 用） ​

bash
npm install
npm run build     # tsup 打包 CLI + 把 src 下的库同步进 dist
npm link          # 链到全局做本地测试

构建产物：

dist/index.js       CLI 本体
dist/library/       业务组件库（组件的唯一来源）+ registry.json
dist/directives/    指令
dist/styles/        样式（nexus.css / nexuspx.css / animations.css）
dist/utils/         工具函数

dist 全部由 src 生成，src/cli 下不存副本。

新增内容 ​

类型放哪还要做什么
组件src/components/<Name>/在 scripts/copy-components.mjs 的 META 里登记分类与说明
指令src/directives/modules/x.ts在 src/cli/lib/registry.ts 加一条 v-x
样式src/styles/base/x.css在 registry.ts 加条目；新文件名要同步 add.ts 的 STYLE_FILE 映射
工具函数src/utils/x.ts在 registry.ts 加条目

改完执行 npm run build，dist 会自动跟着更新。
